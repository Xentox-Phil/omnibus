# Regensburg RVV Bus Simulation + Demand Viewer

Self-contained SUMO bus scenario for Regensburg with a browser-based replay that
also shows a **demand heatmap**. Everything runs from **this folder** — no files
outside it are needed (the folder is its own `uv` project).

## Requirements (on the target machine)
- [`uv`](https://docs.astral.sh/uv/) — the only thing you install by hand.
  It pulls Python + SUMO automatically on first run. Install with:
  `curl -LsSf https://astral.sh/uv/install.sh | sh`
- A web browser
- **Internet** the first time (to install SUMO via uv) and while viewing
  (the map tiles, fonts, and MapLibre library load from the web).

You do NOT manually install Python packages or SUMO — `uv` reads `pyproject.toml`
+ `uv.lock` and sets everything up in a local `.venv/` on first run.
(`.venv/` is gitignored — it is rebuilt automatically, never committed.)

## Quick start (after `git clone`)
```bash
# 1. install uv (once per machine) — see link above
# 2. go to this folder
cd analysis/sumo
# 3a. JUST WATCH the prebuilt simulation (no SUMO install, instant):
bash serve_viewer.sh
#     then open http://localhost:8000/viewer.html
```
That's it to view. The repo already ships a built `viewer_data.json` +
`demand.json` (currently: RVV, 2025-08-01, 05:00–24:00), so the viewer works
immediately. The first `serve_viewer.sh` needs only `python3` (no SUMO).
To regenerate a different day/time, see section C.

## A. Just watch the result (no SUMO needed)
```bash
bash serve_viewer.sh                 # serves this folder on :8000
# open http://localhost:8000/viewer.html
```
The viewer only needs `viewer.html`, `viewer_data.json`, `demand.json`.

## B. Watch the live SUMO GUI
```bash
bash run_gui.sh                      # uv resolves SUMO, opens sumo-gui
```
(macOS note: sumo-gui needs XQuartz; the browser viewer avoids that.)

## C. Rebuild from inputs (new date / time / GTFS)
```bash
bash rebuild.sh                      # defaults: date 20250728, 07:00-08:00
bash rebuild.sh 20250729 0 86400     # different date, full day
```
This runs: (netconvert if needed) -> gtfs2pt -> sumo -> fcd_to_json -> demand,
then you re-run `serve_viewer.sh`.
- `--date` must be inside the GTFS feed's validity window (see `gtfs.zip`).
- Times are seconds-after-midnight (07:00 = 25200).

## Files

**Source / scripts**
- `viewer.html` — the browser viewer (buses + demand heatmap)
- `fcd_to_json.py` — SUMO FCD trajectories -> `viewer_data.json`
- `generate_demand.py` — sample `demand.json` (replace with real demand)
- `run_gui.sh`, `serve_viewer.sh`, `rebuild.sh` — launchers
- `pyproject.toml` — makes this folder a standalone uv project
- `regensburg.sumocfg` — SUMO run config

**Inputs**
- `regensburg.net.xml` — road network (built from OSM)
- `gtfs.zip` — RVV GTFS feed (timetable, stops, routes)
- `gtfs_pt_vehicles.add.xml`, `gtfs_pt_stops.add.xml`, `pt_vtypes.xml`
  — generated by `gtfs2pt` from `gtfs.zip` + network

**Generated (regenerable, can be deleted)**
- `sim.fcd.xml`, `viewer_data.json`, `demand.json`, `out_*.xml`, `*.log`

## Demand JSON schema (for whoever supplies real demand)
```json
{
  "date": "2024-10-19",
  "resolution_min": 15,
  "n_ticks": 96,
  "tick_times": ["00:00", "...", "23:45"],
  "nodes": [
    { "stop_code": "JAHN", "lat": 48.99102, "lon": 12.11224,
      "pressure_norm": [0.45, 0.60, ...] }   // length n_ticks, 0..1, drives color
  ]
}
```
Viewer needs per node: `lat`, `lon`, `pressure_norm` (length = `n_ticks`), plus
top-level `resolution_min`. Other fields (`pressure_s`, `baseline_s`, `event_s`,
`events`) are accepted and ignored. Save the file as `demand.json` and reload.
